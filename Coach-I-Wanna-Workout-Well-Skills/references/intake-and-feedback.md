# 接待与反馈

供总控与 Train Well 在制定完整计划、复盘或交接时按需读取。只收集影响当前决策的信息；当前对话已有资料不重复问。

## 首次计划问卷

可用下面的紧凑格式邀请用户回答；未知可留空。涉及安全的缺口仍需澄清，不能用假设补齐。

```text
目标：本阶段最想改善什么，有没有期限？
基础：年龄或年龄段、训练经验、现在的运动安排。
条件：每周几天、每次多久、健身房或家中、有哪些器械？
安全：现在有没有疼痛或不适，已知疾病、影响运动的用药或医生限制？是否处于孕产期？
偏好：喜欢或不愿做哪些动作，过去最难坚持的是什么？
按需补充：身高体重及近期趋势（饮食、体重管理或相关目标需要时）。
```

不要要求真实姓名、身份证、住址或无关健康资料。用药只了解与运动、饮食或补剂风险相关的内容，不调整处方。情绪或急性症状需要马上处理时先处理眼前问题。

问卷不是通行证：症状、疾病和特殊人群的具体适用性依对应知识文件处理。用户不愿提供关键资料时，解释该信息会影响哪项决策，给一般知识或条件性框架，避免输出未经筛查的个体处方。

## 当前对话中的最小档案

只整理必要字段，并区别用户报告、估算与未知：

| 内容 | 记录口径 |
| --- | --- |
| 目标与条件 | 本阶段优先目标、年龄段、经验、排期、器械、偏好 |
| 安全限制 | 用户报告的症状、相关疾病或医疗限制；未知明确标注 |
| 当前计划 | 版本或日期、训练日、动作、工作组次、RIR、进阶条件 |
| 实际反馈 | 训练日期、完成情况、主要动作表现、恢复与症状变化 |
| 当前调整 | 改动与理由、观察指标、下一次反馈窗口 |

体重等趋势保留测量条件，不把估算热量或设备体脂当成已核实事实。用户纠正信息时更新当前字段，不保留相互矛盾的结论。

## 训练后反馈

首周可在第一次训练后反馈；之后按需要复盘。用户不必记录所有指标，先抓影响进阶和安全的内容：

```text
日期 / 训练日：
实际用了多久，哪些动作完成或漏了：
主要动作：重量 × 每组次数 / 最后一组大约还能做几次：
有没有动作变形、疼痛或其他不适：
训练后及次日：症状变化、酸痛是否影响日常活动：
```

新手 RIR 是粗略自评，结合动作质量和实际次数判断，不把自评分当成精确测量。视频仅评估可见部分，不推断看不到的技术或作医学诊断。

## 每周复盘

先比较计划与实际：完成几次、主要动作是否进步、训练时长是否合适，以及睡眠、疲劳和生活阻碍。体重目标才补同条件下的体重趋势与饮食执行情况，避免对单次波动反应。

根据反馈选择维持、微调或减量；说明主要依据。一次漏练或表现不佳通常先观察，不把它定义为平台期。缺少足够记录时先补关键记录，不声称找到了停滞原因。疑似危险症状立即处理，不等每周复盘。

## 交接摘要

用户需要在下次对话继续时，若未启用长期档案或保存失败，提供以下精简摘要，并明确它没有被跨对话自动保存：

```text
目标与条件：
安全限制 / 待确认：
当前计划与进阶规则：
最近实际表现：
这次调整与原因：
下次需要观察：
```

需要跨对话档案时使用 [本地长期档案](long-term-memory.md)；此模板本身不保存数据或安排自动提醒。
